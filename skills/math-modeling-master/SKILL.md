# 数学建模全流程总控指挥引擎 (math-modeling-master v4.0)

本文件是 math-model 家族的**唯一总控编排层**：它不亲自产出任何竞赛交付物，只负责三件事——**分配 G0~G7 阶段任务、执行 CB-1~CB-12 熔断门禁验收、在阶段之间做交接与召回（G6 召回由 `math-model-paper` 主责发起，总控下达召回令）**。本总控的输入是赛题、赛制与队伍能力画像，输出是 `decisions/`、`docs/`、`code/`、`figs/`、`paper/`、`review/` 六类产物的**流转状态与验收裁决**（全部落盘于 `state/gate_log.jsonl`）。

**适用范围**（本总控介入）：
- 把这场比赛从选题跑到交付；
- 排 72/96 小时计划；
- 检查能不能进下一阶段；
- 多个子技能接力协调。

**不适用范围**（本总控不介入）：只要单点产物，**严禁**由本总控代劳，必须直调对应子技能——只要图 → `math-model-visualize`；只要摘要/排版 → `math-model-paper`；只要扰动与稳健性 → `math-model-solve`；只要假设与方程 → `math-model-formulate`；只要数据剖析 → `math-model-decomp`；只要选题评分 → `math-model-strategy`。本总控对单点任务的正确动作是**不介入**。

> 【系统级最高优先执行警示】
> 本总控统筹调度全家族技能，全流程必须严格执行 **CB-1 ~ CB-12 十二项熔断门禁**（本文件 §3 与 `scripts/CANON.md §2` 等价，**如有出入以 CANON 为准**）。
> **【严禁】**AI 偷懒跳步、**【严禁】**用“篇幅所限略去推导”敷衍、**【严禁】**输出通用八股模板。
> 每个阶段收口必须过 checkpoint：任一门禁不达标即触发**回退协议（§4）**——打回本阶段重做，根因在紧邻上游则回溯上一阶段；发现点 ≠ 根因点时（**不限相邻**）按 §4『多跳回溯』处理；同一 checkpoint 最多 2 轮，2 轮仍失败启动降级策略并标注风险，**【严禁】**无对象、无轮次、无留痕的“无条件打回”。

### 1.3 冲突裁决规则

1. **总控规则 > 子技能局部规则**：本文件的阶段码、门禁码、回退协议对全家族有最高裁决权；子技能 SKILL.md 的局部约定与本文件冲突时，一律以本文件为准（数值类冲突见第 3 条）。
2. **数值唯一真相源 = `state/frozen_results.json`**：一切跨 skill 的结果数值以该文件为准；论文与图件只允许是它的下游投影。**【严禁】**反向以论文/图中的数字回改该文件。
3. **同一数值多处出现时以 CANON §4 数值常量唯一源为准**（页数 `26–40 页`（理想 `30–36 页`）、配图 `15~25 幅（≥15）`、扰动 `±5%、±10%、±20%`、关键词 `4~5 个`、参考文献 `1~5 个（建议 3~5 个）` 等），全库逐字一致，**【严禁】**各文件自造变体。
4. **阶段码与门禁码不可混用**：`G0`~`G7` 是阶段码（无连字符），`CB-1`~`CB-12` 是熔断门禁码（有连字符）。

### 1.4 数据契约 schema 指针（frozen_results.json 哈希协议）

- **路径基准**：`<project-root>/state/frozen_results.json`
- **schema**：字段结构（`schema_version` / `frozen_at` / `hash_sha256` / `metrics[]` / `decisions[]` / `figures[]`）以 **CANON §3.4** 为准，实现细节以 **`math-model-solve`** SKILL.md 为准；本总控不复制 schema 正文，只做消费与校验。
- **【强制】哈希协议**：写入后立即计算 `hash_sha256`（对**除去该字段本身**的规范化 JSON 计算）；G6 终检时**由 `math-model-solve` 执行重算，`math-model-paper` 在 Round 2 复核比对，本总控抽查；任一不一致判 CB-7 失败**。
- **【强制】更新顺序**：改数值 → **先**更新 `frozen_results.json` 并重算哈希 → **再**级联更新论文/图。**【严禁】**反向。

## 4. 检查点与回退协议（Checkpoint & Fallback Protocol）

- **checkpoint 定义**：每个**阶段码**（`G0`~`G7`）结束时各设 1 个检查点；checkpoint 由总控主持，子技能列席。
- **回报闭环**：回退后子技能向总控**回报**重做结果并重新提交 checkpoint；总控在 `state/gate_log.jsonl` 追加本轮通过行。
- **判定**：任一**该阶段适用**的门禁（见「本阶段须通过的门禁」钩子表）不达标 → 该 checkpoint 判 `FAIL`；全部达标 → 判 `PASS` 并放行。
- **回退动作**：
  1. 默认**打回本阶段**重做（重做范围 = 未达标门禁涉及的交付物）；
  2. 若根因在**上游产物错误**（如数据错、推导错导致下游连带失败）→ **回溯至上一阶段**重做，下游随之重跑；
  3. **默认只允许打回本阶段或紧邻上游阶段**。唯一例外见下方『多跳回溯』；同时**【严禁】**在无根因判定时随意扩大回退范围。
- **多跳回溯（唯一例外）**：当**发现点 ≠ 根因点**时（**不限相邻**，含相邻回退），允许回溯至根因阶段，但必须满足三条：
  1. `state/gate_log.jsonl` 同时记录 `root_cause_phase` 与 `target_phase`（**相邻回退同样记码**，见 §4 字段定义）；
  2. 轮次在根因阶段 checkpoint 重新计数；
  3. 下游产物标记为待重验，重跑各自 checkpoint。
- **轮次上限**：同一 checkpoint **最多 2 轮**。**2 轮仍失败 → 启动降级策略**（三选一或组合）：
  - **缩减范围**（`action = fallback_reduce_scope`）：削减非核心子问/非核心图件，保住主线完整；
  - **换对冲方案**（`action = fallback_alternative`）：切换到**对冲方案**——由 `math-model-formulate` 在 G2 推导稿中登记的 Hedge 模型，或 `math-model-visualize` 备用图型；对冲方案必须在本 checkpoint 之前已写入对应产物，否则该降级选项视为不可用；
  - **记录风险并放行**（`action = fallback_accept_with_note`）：进入下一阶段，但**【强制】**在交付物中以显式标注声明该缺口（位置、影响面、未修复原因）。
- **凭据（留痕）**：每轮回退必须向 `state/gate_log.jsonl` **append 一行**（相对路径基准 = 项目工作区根）；**同一 checkpoint 多条 CB 同时 FAIL 时，每条 CB 单独 append 一行**（`gate` 为单值，禁止合并成一行）：

```json
{"ts":"YYYY-MM-DDTHH:MM:SS","gate":"CB-7","phase":"G3","verdict":"FAIL","round":2,"action":"fallback_reduce_scope","root_cause_phase":"G2","target_phase":"G2","note":"冻结值与论文数值不一致"}
```

字段固定为 9 个：`{ts, gate, phase, verdict, round, action, root_cause_phase, target_phase, note}`；`verdict ∈ {PASS, FAIL}`，`gate ∈ {CB-1..CB-12, S-1..S-5}（S-x 为 strategy 门禁）`，`round ∈ {1, 2}`，`action ∈ {proceed, hold, redo_phase, rollback_upstream, fallback_reduce_scope, fallback_alternative, fallback_accept_with_note}`，
`target_phase` **恒填**（打回本阶段则等于 `phase`），`root_cause_phase` 在**未做根因判定**时才填 `null`（相邻回退同样记码，供 G7 归因聚合），`note` 为一行事实摘要。
**字段补注**：`phase` = **发现点阶段**（该门禁判 FAIL 时所处阶段）；`root_cause_phase` = **根因阶段**（根因所在阶段）；`round` = **根因阶段轮次**（多跳回溯后在根因阶段 checkpoint 重新计数；未发生多跳回溯时即本阶段轮次）。G7 复盘必须消费本日志。

**action 取值映射**：`proceed` = 放行、`hold` = 暂缓、`redo_phase` = 本阶段重做、`rollback_upstream` = 打回上游、`fallback_*` = 降级三选一（对应上方三选项）。

## 6. 核心质量红线（与 CB 门禁去重后的独立红线）

以下 8 条**不构成门禁、无法用单一勾选项判定**，全生命周期常驻：

- **R1 数据真实不可伪造**：严禁伪造、主观捏造任何数据样本、求解结果或统计指标。
- **R2 结论必须可溯源**：任何结论性陈述必须能溯源至**代码计算 / 数学推导 / 规范文献**三选一，悬空无源即违规。
- **R3 禁“注意/注：”说教字眼**：正文、公式解说、图注中严禁出现“注意”、“注：”、“注1：”、“需要注意的是”等提示残留；前提与参数一律以客观学术句融入（参数写“其中…”，数据写“数据来源：…”）。
- **R4 关键信息与“针对问题X”加粗（纯黑）**：摘要段首引导词、核心量化数值、自研微创新算子名、结论点睛句 `\textbf` 加粗，颜色恒 `#000000`（摘要段首细则见 CB-8）。
- **R5 禁彩色文字与彩框**：严格执行 CANON §4 **颜色三分法**——① 正文/标题/图表文字恒 `#000000` ② 数据图可用感知均匀色盘（Viridis/Cividis/RdBu_r 及 8 色顶刊 hex） ③ Draw.io 与表格强制黑白；三条并存不冲突。
- **R6 参考文献真实可查禁伪造**：数量统一 `1~5 个（建议 3~5 个）`（CANON §4 唯一源），来源网上精确可查，严禁凭空捏造。
- **R7 禁致谢/结语等非学术尾章**：模型评价后紧接参考文献，写完主体即彻底结束，严禁致谢、结语、心得体会等无关尾章。
- **RL-8 假设全生命周期贯通**：前置假设必须在后文公式中显式激活为约束，并在模型评价中反思假设失效影响。

**已并入门禁、此处仅存引用（详见 §3）**：篇幅与零空白 → **CB-1**；配图密度与防重叠 → **CB-2**；流程图黑白与零穿透 → **CB-3**；公式包裹 → **CB-4**；分段节奏 → **CB-5**；大 O 剔除与扰动 → **CB-6**；附录代码纯净 → **CB-7**；摘要硬性 → **CB-8**；对比图组 → **CB-9**；辅助章节极简 → **CB-10**；开放题数学化 → **CB-11**；反上帝视角与元语言 → **CB-12**。
