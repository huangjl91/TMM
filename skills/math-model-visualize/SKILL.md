# 出版级科研可视化与 Draw.io 流程图引擎 (math-model-visualize)

```
┌──────────────────────────────────────────────────────────────┐
│ math-model-visualize · 可视化引擎（G4）                     │
├──────────────────────────────────────────────────────────────┤
│ 铁律：顶刊级图件，DPI ≥ 300，双基准路径严禁混用             │
└──────────────────────────────────────────────────────────────┘
```

本技能负责数学建模竞赛的 **顶刊级数据可视化与专业架构制图**，践行“先想论点、再定图型、按需定寸、经典黑白纯正、拒绝垃圾图”的工业级标准。**输入**为 G3 冻结数值、G1 清洗前后数据与 G2 机理流程，**输出**为 `figs/fig_XX_*.png`（300 DPI）与 `figs/*.drawio`，交由 `math-model-paper` 排版。

---

## 输入与输出契约

> **路径基准**：本节及全文所有相对路径，一律相对**项目工作区根**（不是 skill 目录）。

**输入（上游供稿）**

| 输入产物 | 内容 | 本技能用途 |
|---|---|---|
| `state/frozen_results.json` | G3 冻结数值：目标值、灵敏度、算法改进前后指标 | 数值图、收敛图、CB-9 第②处对比数据 |
| `docs/G1_赛题解构与数据剖析卡.md` | 第 7 字段「清洗前后同口径对比数据」及其 EDA 清洗数据 | EDA 探索图、CB-9 第①处对比数据 |
| `docs/G2_模型推导稿.md` | 符号表、方程组、机理流程 | 物机理图、Draw.io 架构与流程图 |
| CB-9 两处对比数据 | 清洗前后（G1 供）+ 算法改进前后（G3 供） | §1.5 Before-vs-After 对比图组 |

**输出（本阶段产物）**

- `figs/fig_XX_*.png`：`XX` 为两位序号，300 DPI 位图（规格见 §1.7）；
- `figs/*.drawio`：Draw.io 流程图源文件，另导出 PDF/SVG。

**消费方**：`math-model-paper`（单图 `0.7–0.85\textwidth`，并排 `0.48\textwidth`）。

## scripts/ 使用说明

> **双基准警告**：本节中 `<skill-dir>` 相对**本技能目录**（`math-model-visualize/`，脚本随技能走），而 `figs/` 相对**项目工作区根**（同「输入与输出契约」节的路径基准）。两种基准不同，严禁互相套用相对路径。

【强制】本技能自带图件机检脚本 `math-model-visualize/scripts/figure_lint.py`，出图后禁止只靠肉眼交卷：

- **用法**：
  ```
  python <skill-dir>/scripts/figure_lint.py --dir <project-root>/figs --min-dpi 300
  ```
- **路径基准**：`<skill-dir>` 指向本技能目录（脚本本体所在），`--dir` 指向项目工作区根下的 `figs/` 目录，二者基准不同；
- **功能**：检查 `fig_XX_<slug>.png` 两位序号命名、ASCII slug（禁空格与中文/全角字符）、DPI ≥300；**缺 Pillow 时降级为仅命名与存在性检查**（打印 SKIP 提示，不判失败）；
- **退出码**：`0` = 无警告；`1` = 有警告（低 DPI / 空目录 / 命名不合规）；`2` = 目录不存在或不可读；
- **触发时机**：**G4 出图后立即执行**（本批图件交付前必跑）+ **G6 终检召回时复跑**（全篇图件地毯式复查的机检前置步骤）；退出码非 0 即按 CB-2 打回 G4 修复后重跑。

## 1. 高密度与强论证铁律（严禁乱来画图）

### 1.1 作图前“论证三问”
1. 这张图要支撑的数学结论是什么？
2. 如果没有这张图，结论的证明力度是否坍塌？
3. 图型是否与数据结构达到最佳匹配？

### 1.2 高密度配图原则（全篇 15~25 幅（≥15））

按五类分解配图额度（三问制）：

| 类别 | 幅数 |
|---|---|
| EDA 探索 | 2~4 |
| 每个子问题求解与检验 | 3~5 |
| 灵敏度/稳健性分析 | 2~4 |
| Before-vs-After 对比图组（CB-9） | 2~4 |
| 系统架构与物理机理 | 1~2 幅 Draw.io 矢量图 |

- **三问制加总**：下限 `2+9+2+2+1 = 16 ≥ 15` ✓；上限 `4+15+4+4+2 = 29`；
- **精简规则**：15 为硬门槛，超过 25 幅须按「多 Panel 合并 / 同类子图并排」精简；
- **全篇目标 15~25 幅（≥15）**：低于 15 幅判不合格（触发 CB-2），超出 25 幅必须精简合并；
- 四问制按“每问 3~5 幅”同理递增，更须向上限 25 幅收敛，禁止无上限堆图。

### 1.3 拦截 10 种科研画图禁忌与替换策略
- 禁忌 1：小样本画均值柱状图（$N < 10$ 隐藏分布） $\to$ **改用**：散点抖动图 (Stripplot) 或蜂群图 (Swarmplot)；
- 禁忌 2：滥用饼图与 3D 饼图（面积角度判断误差大） $\to$ **改用**：降序排列的水平条形图或堆叠条形图；
- 禁忌 3：伪双 Y 轴强行关联（制造虚假相关） $\to$ **改用**：上下共享 X 轴的双子图；
- 禁忌 4：离散分类变量用折线连接（暗示连续变化） $\to$ **改用**：带误差棒的点图或柱形图；
- 禁忌 5：使用彩虹 (Jet/Rainbow) 色系（感知非线性假峰） $\to$ **改用**：感知均匀的 Viridis、Cividis 或双极分流 RdBu_r（完整色盘见 §1.3.1）；
- 禁忌 6：坐标轴随意截断（柱状图不从 0 起始夸大差异） $\to$ **强制**：条形图基准必须为 0；散点图截断必须标明断轴；
- 禁忌 7：中文乱码与负号方块 $\to$ **强制**：配置 SimHei/Source Han Sans 并指定 `axes.unicode_minus=False`；
- 禁忌 8：图例文本覆盖核心数据轨迹 $\to$ **修正**：外置图例或置于绝对空旷象限；
- 禁忌 9：图面文字过小（缩放后低于 6pt 不可读） $\to$ **标准**：标签 8–10pt，刻度 7–9pt，全图最小字符 $\ge 6\text{pt}$；
- 禁忌 10：图无误差交代 $\to$ **铁律**：带有误差棒/置信带的图，图注中必须写明是 SD、SEM 还是 95% CI，并交代样本量 $n$。

#### 1.3.1 顶刊色盘与颜色三分法（禁忌 5 扩展）

【铁律】**Nature/Science 风格分类色序**，8 色 hex 逐字取自 CANON §4 唯一源，禁止自造变体：

| 序号 | hex | 序号 | hex |
|---|---|---|---|
| 1 | `#E64B35` | 5 | `#F39B7F` |
| 2 | `#4DBBD5` | 6 | `#8491B4` |
| 3 | `#00A087` | 7 | `#91D1C2` |
| 4 | `#3C5488` | 8 | `#DC0000` |

**色盘选用规则**：

- **分类变量**：按上表 8 色顺序依次取色（分类色序优先），类别超过 8 个时循环取色并靠图例区分；
- **顺序型（连续数值）**：用感知均匀色盘 Viridis / Cividis；
- **发散型（正负、双向偏离）**：用 RdBu_r。

【颜色三分法】以下三条**并存不冲突**，按对象分流：

1. **正文、标题、图表内文字**恒为纯黑 `#000000`；
2. **数据图**（散点/折线/热力/箱线等）可用感知均匀色盘或顶刊 8 色 hex；
3. **Draw.io 流程图与表格**强制黑白（黑框白底，见 §2.2）。

### 1.4 图题命名极简规范（图下仅注明“这是什么图”）
- **图下方标题 (Caption) 极简规范**：数据可视化图表下方只需简练说明“这是什么图”（图题直接交代核心对象与图型），严禁在图题下方堆砌冗长无谓的现象描述（如“图X展示了随……变化轨迹……”）或分析废话；
- **标准图题命名规范**：
  - 规范示例：`\caption{三种算法迭代收敛曲线对比}`、`\caption{各品类蔬菜历史销量分布箱线图}`、`\caption{不同温度工况下含水量时序演化轨迹}`；
  - 禁忌表现：严禁在 Caption 下方写小作文、重述图表走向。具体机理与因果分析放在正文相关自然段落中推进，图注本身保持纯粹、极简、一目了然。

### 1.5 Before-vs-After 对比图组规范（CB-9 落地，两处强制）

【熔断】全篇必须在**两处**各出一组“处理前 vs 处理后”对比图，**供数据方（G1/G3）未按时交付对比数据（`data/raw/`、`data/clean/`）→ 打回对应阶段补数据；数据齐备但图件缺失/不合规 → 打回 G4 补图**：

- **第①处 数据预处理/去噪处**：原始含噪时序 **vs** 滤波平滑时序。
  - 数据来源：`math-model-decomp` 的 EDA 清洗结果，**由 `math-model-decomp` 落盘至 `data/raw/` 与 `data/clean/`（同口径对比数据），登记于剖析卡第 7 字段**；本技能据此取 `docs/G1_赛题解构与数据剖析卡.md` 第 7 字段「清洗前后同口径对比数据」所指数据与 `figs/fig_XX_*.png` 路径；
- **第②处 核心算法改进处**：Baseline 目标值/轨迹 **vs** 改进后目标值/轨迹。
  - 数据来源：`math-model-solve` 冻结在 `state/frozen_results.json` 中的改进前后指标（同一指标、同一单位、同一精度）。

【排版与图注规范】

- **左右并排双子图，共享 Y 轴**（`plt.subplots(1, 2, sharey=True)` 或 gridspec 同列 `sharey`），量纲一致才可并排；
- **各自子图标题仅写**“处理前 / 处理后”或 “Baseline / 改进后”，不得附加任何结论性、分析性词语；
- **整图 Caption 仅“对象 + 对比图组”**，例：`\caption{销量时序去噪前后对比图组}`、`\caption{订货策略目标值 Baseline 与改进后对比图组}`；
- **严禁在图下写分析文字**：升降幅度、优劣结论一律进正文段落（见 §1.4）；
- 插入宽度按并排规格 `0.48\textwidth`（与 `math-model-paper` 排版衔接）。

### 1.6 多 Panel 复合图设计

- **布局**：优先 `plt.subplot_mosaic([["a","b"], ["c","c"]])`（需 matplotlib ≥3.1；键名即 panel 名，直观可读），或 `fig.add_gridspec(nrows, ncols)` + `fig.add_subplot()` 精细控制；
- **列数**：单行 **2~3 列为宜**，严禁 4 列及以上挤压导致字号跌破 6pt；
- **共享轴规则**：同一物理量的 panel 强制 `sharex` / `sharey`；共享后仅最外侧 panel 保留刻度标签，内部 panel 用 `labelbottom=False` / `labelleft=False` 消除重复；
- **Panel 编号**：`(a)(b)(c)` 置各子图**左上角**，用 `ax.set_title("(a)", loc="left", fontsize=9)` 或 `ax.text(0.01, 0.98, "(a)", transform=ax.transAxes, va="top")`，与子图标题左对齐；
- **图注**：整图仅一个 Caption（对象 + 图型），各 Panel 标题只写短语，不写句子；
- **与排版衔接**：整组作为单图插入时占 `0.7–0.85\textwidth`；两幅复合图并排时各占 `0.48\textwidth`（与 `math-model-paper` 规格一致）。

### 1.7 输出规格（DPI / 格式 / 字体）

【强制】

- **位图统一 300 DPI**：`fig.savefig(path, dpi=300, bbox_inches="tight", facecolor="white")`，禁止零 DPI 或默认 100 DPI 交付；
- **格式**：`PNG` 用于正文插入（`figs/fig_XX_<slug>.png`）；`PDF` 用于矢量导出（数据图矢量版与 Draw.io 流程图导出 `PDF` / `SVG`）；
- **中文字体**：沿用禁忌 7（SimHei / Source Han Sans + `axes.unicode_minus=False`），确保 PNG 与 PDF 中无乱码、无负号方块；
- **Draw.io 交付**：保留 `figs/*.drawio` 源文件，同时导出 PDF/SVG 供排版与缩放；
- **收边**：保存前强制 `plt.tight_layout()` 或 `figure(layout="constrained")`（后者需 matplotlib ≥3.6），配合 `bbox_inches="tight"` 杜绝裁切。

## 2. Draw.io 经典黑白流程图标准（严禁花哨）

### 2.1 三大基础图元法定语法
1. **圆角矩形 (Rounded Rectangle)**：**仅且只能用于系统起始输入 (Input/Start) 与最终解输出 (Output/End)**；
2. **菱形 (Diamond)**：**仅且只能用于条件判断、逻辑分支与分类准则 (Condition)**，分支箭头标明 `Yes` / `No` 或对应不等式；
3. **方矩形 (Standard Rectangle)**：**其余所有常规计算、数据处理、变异交叉、算子执行一律强制使用方矩形**。

### 2.2 经典纯正的黑框白底铁律
- 全图图元背景强制纯白 (`#ffffff`)，边框强制黑色 (`#000000`)，严禁彩色大色块填充；
- 边框线宽统一 `1pt` 或 `1.5pt`，核心自研算子可用 `2pt` 强调；文字黑色 `Times New Roman` 或 `KaiTi` / `SimSun`，字号 8–10pt。

### 2.3 箭头流动逻辑与零冲突拓扑
- 连线严禁重叠黏连，严禁斜切穿透无关图元；
- 一律采用标准直角正交连线；主求解流沿自上而下或自左向右推进；迭代反馈回路必须从最外侧规整平滑绕回；
- 箭头必须吸附在图元边缘连接点，杜绝虚空悬挂。
- **AI 完工自检闭环**：自检发现连线混乱或图元混用，**强制推倒重绘**。

## 3. 完工全图地毯式自检与防重叠/防穿透门禁 (Post-Completion Inspection Gate)

本门禁分**两级时点**执行，坚决杜绝“带病交卷”：

- **G4 出图自检（第一道）**：每幅图/每张流程图生成后**立即**执行 §3.1、§3.2 逐项排查，通过后方可继续出下一幅图；
- **G6 终检召回（第二道）**：论文完稿后，**G6 终检由 `math-model-paper` 主责发起召回**（召回令由总控下达），本技能与 `math-model-solve` 被召回联合执行，按 §3.3 执行全篇地毯式复查与重构。

本技能的激活窗口为 G4 与 G6 两个阶段（见总控阶段沙盘）。

### 3.1 数据图表文字与数字防重叠铁律 (Data Chart Anti-Overlap)
- **坐标轴刻度与标签重叠排查**：
  - 若 X 轴分类过多或日期密集导致文字/数字相互叠压，强制设置角度倾斜：`plt.xticks(rotation=30, ha='right')`；若为密集连续数值，强制使用 `matplotlib.ticker.MaxNLocator(nbins=6)` 进行抽稀截断；
- **柱顶与散点数据标注重叠排查**：
  - 严禁多个数字贴脸重叠或压在折线/柱体边界上！标注必须设置安全偏移量（如 `text(x, y + offset, ...)`）；数据点过于密集时，仅保留极值点标注，或使用第三方库 `adjustText`（需 `pip install adjustText`；**未安装时降级方案 = 仅保留极值点标注**）自动弹开防撞；
- **图例遮挡排查**：
  - 严禁图例遮挡数据折线、柱体或坐标轴标题！密集复杂图表强制采用外置图例（`bbox_to_anchor=(1.02, 1), loc='upper left'`）或放置在绝对无数据的空旷角落；
- **边距挤压排查**：
  - 画布保存前强制调用 `plt.tight_layout()` 或设置 `figure(layout='constrained')`（需 matplotlib ≥3.6），彻底杜绝图表四周文字被裁切或挤压重叠。

### 3.2 Draw.io 流程图箭头防穿透与防黏连铁律 (Flowchart Anti-Penetration)
- **严禁箭头穿过矩形内部 (Zero Arrow Penetration)**：
  - 连线必须从图元外部正交绕行，**绝对禁止任何箭头线段从方矩形或菱形图元内部横穿穿透**！
  - 必须使用规范的端口吸附与正交连线路由（`edgeStyle=orthogonalEdgeStyle;exitX=...;entryX=...`），确保进出连线严格从边框引出与接入；
- **严禁箭头与连线相互重叠黏连 (Zero Line Collision)**：
  - 保持至少 25pt 以上的连线间距，严禁两条连线重合在一条线上；
  - 迭代回退循环（Loop Back）必须统一从最外围平滑引回，严禁在主流程框图内部交叉穿行；
- **连接点吸附严密**：箭头必须精准吸附在图元边缘正中或指定锚点，严禁虚空悬挂或穿插错位。

### 3.3 完稿全图强制复查与重构工作流 (Mandatory Inspection Workflow)
- **全篇完稿后强制逐图地毯式审查**：
  1. 逐一打开/检查全篇所有数据图：重点查看刻度数字是否叠压、数据标签是否撞车、图例是否压字；
  2. 逐一打开/检查流程图与架构图：重点查看箭头是否穿透了矩形、连线是否重合黏连；
- **触发推倒重画机制**：一旦发现任何一幅图存在文字数字重叠、或箭头穿透矩形、或箭头黏连，**判定为画图失败，必须立即修改绘图代码或调整 Draw.io 节点坐标重新生成替换，自检无误后方可最终交付**！
