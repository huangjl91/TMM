# 竞赛策略、选题决议与赛后复盘引擎 (math-model-strategy)

```
┌──────────────────────────────────────────────────────────────┐
│ math-model-strategy · 选题决议引擎（G0/G7）                 │
├──────────────────────────────────────────────────────────────┤
│ 铁律：五维评分锁题，复盘闭环回写年迭代                       │
└──────────────────────────────────────────────────────────────┘
```

本技能负责数学建模竞赛全流程的两个端点阶段：**G0 赛前策略与选题决议**（T00:00–T06:00）与 **G7 赛后复盘**（赛后 48h 内）。输入是赛题列表、赛事规则与队伍能力画像，输出是 `decisions/G0_选题决议卡.md`（下游进入 G1 解构）与 `review/G7_复盘改进卡.md`（闭环至下届竞赛）。**选题是全链路杠杆最大的决策——一旦锁题，全队不得回头；T06:00 之后的任何换题都必须付出整条链路重排的代价。**

## 1. G0 赛前策略（T00:00 起 6 小时内完成）

### 1.1 赛事情报与规则勘察

- **赛制**：72h（国赛）/ 96h（美赛）；是否允许中文作答、是否要求 English Abstract；
- **评分权重**：通常为模型 40% / 论文 30% / 结果 20% / 创新 10%，**必须按当年官方规则逐项校准**，禁止沿用去年口径；
- **交付物清单**：论文（正文 `26–40 页`，理想 `30–36 页`）、PPT、代码附录、支撑材料四列清单；提交通道与截止时刻须写入全队硬提醒（截止前 2h 与 0.5h 各一次）；
- **往年特等奖论文调研**：只看 3 篇的结构、图表密度与章节配比，**【严禁】**抄袭其内容与数据结论。

### 1.2 队伍分工与时间预算

- **三角色**：建模手 / 编程手 / 写作手。可 2 人兼任，但**不可 0 人负责**——每个阶段必须有且仅有一名第一责任人（DRI）；
- **赛制预算表（72h / 96h）**（时间窗与 CANON §1 阶段码逐字对齐）：

| 阶段 | 时间窗（72h） | 时间窗（96h） | 主责角色 |
|---|---|---|---|
| G0 策略与选题 | T00:00–T06:00 | T00:00–T06:00 | 全员（建模手主持） |
| G1 解构与剖析 | T02:00–T12:00 | T02:00–T14:00 | 建模手 |
| G2 机理建模 | T12:00–T30:00 | T14:00–T40:00 | 建模手 |
| G3 数值求解 | T18:00–T42:00 | T22:00–T52:00 | 编程手 |
| G4 科研绘图 | T24:00–T48:00 | T30:00–T60:00 | 编程手 + 写作手 |
| G5 论文写作 | T42:00–T66:00 | T52:00–T84:00 | 写作手 |
| G6 质检与交付 | T66:00–T72:00 | T84:00–T96:00 | 三方联合 |
| `G7` 赛后复盘 | 赛后 48h 内 | 赛后 48h 内 | math-model-strategy（三角色全员） |

> **表注**：本表为 CANON §1 **授权开工窗口**（允许重叠），72h 列合计 **112h** ≠ 72h，96h 列合计 **148h** ≠ 96h，两者同为授权窗叠加、**均非预算**；排期与 G7 偏差审计一律用**接力区间**（72h 赛制合计 72h、96h 赛制合计 96h，见 §3.1 与 G7 模板 §4），**不得**把授权窗口时长当预算时长。

- **交接节拍**：每 **12h** 一次全员同步（15 分钟站会），产物必须落盘到约定路径，**【严禁】**只存在于聊天记录或某人本地；
- **睡眠预算**：单人连续工作 ≤ 16h 必须轮换，交接文档先于人离场。

### 1.3 时间铁律

【铁律】**T06:00 前必须完成锁题**；T06:00 后原则上**禁止换题**，特殊情况需全员书面同意并记录于决议卡（§2.4 第 4、6 字段），口头同意无效（见 S-2）。

## 2. G0 选题决议（五维评分卡）

### 2.1 五维评分卡（每维 0~10 分，加权求和，满分 10.00）

| 维度 | 权重 | 评分要点 |
|---|---|---|
| 数据完备度 | 0.30 | 附件是否齐全、样本量、缺失率、是否含未来信息陷阱 |
| 方法匹配度 | 0.25 | 题目本质与队伍擅长方法域（12 类）的重合度 |
| 工作量可控度 | 0.20 | 72/96h 内能否完成推导+求解+ `15~25 幅（≥15）` 图 + `26–40 页` 论文 |
| 创新空间 | 0.15 | 微创新算子可设计空间、对冲模型可搭性 |
| 竞争风险 | 0.10 | 热门题扎堆程度、是否为经典题型变形 |

**【强制】** 权重之和恒等于 **1.00**；改动任一权重必须同步改动至少另一项并重算总和，且经全员确认后写入 §3.4 闭环记录。

### 2.2 一票否决红线（任一触发即排除该题，共 5 条）

1. 核心数据缺失率 **> 30%** 且无法插补/替代获取；
2. 题目所需数据全部位于“未来信息”（无法通过时空防火墙）；
3. 纯开放主观题且无任何可量化抓手；**“无可量化抓手”的判定**：题目所有问项均无法转化为至少 1 个可计算指标或可判定规则，且队伍 **30 分钟**内列不出任何候选指标 → 成立；
4. 题目工作量预估 **> 队伍 1.5 倍可用工时**；**可用工时 = 赛制小时数 × 队伍人数 × 有效系数 0.7**（扣除睡眠、吃饭、提交等待），例：`72h × 3 人 × 0.7 ≈ 151 人·时`；**预估工时 > 1.5 × 可用工时即否决**；
5. 队伍无人掌握该题 12 类本质中的任何一个主方法。

【熔断】一票否决**先于**评分卡执行（S-3）：高分不得豁免否决，被否决的题不得进入加权求和。

### 2.3 评分与决议流程

1. 每题独立打分（五维 0~10 分 × 权重 → 加权总分），评分人不少于 2 人取均值，分差 > 2.0 分时当场陈述理由重评；
2. 与 `math-model-decomp`(G1) 的**难易度标签、12 类归类互传校验**：仅在 **T02:00–T06:00 授权并行试解构窗口**内，decomp 对**候选题目**产出《试解构备忘》`decisions/G0_试解构备忘_<题号>.md`，其 12 类归类初判与难易初判**回填**本评分卡（见『输入与输出契约』回传通道行）；**正式剖析卡 `docs/G1_赛题解构与数据剖析卡.md` 必须在 T06:00 锁题、由 §2.4 决议卡放行后创建**，评分卡的回传数据只来自试解构备忘，两者不得混用；
3. **决胜规则**：分差 < **1.0 分**时，**优先数据完备度高者**；
4. 产物：`decisions/G0_选题决议卡.md`（schema 见 §2.4），锁题时间戳必须 **≤ T06:00**。

### 2.4 《G0 选题决议卡》schema（缺一字段即判 G0 未完成）

```
1. 候选题目列表与逐题五维得分   （题目/五维分数/加权总分/排名）
2. 一票否决触发记录             （红线编号 1~5 / 触发题 / 证据）
3. 最终选题与理由               （≤200 字）
4. 锁题时间戳                   （YYYY-MM-DDTHH:MM，必须 ≤ T06:00）
5. 队伍分工确认                 （建模手/编程手/写作手 三角色签名）
6. 预案                         （主选题中途崩盘时的备选题 + 切换判据 + 触发审批人）
7. 回传给 G1 的输入清单         （题干/附件路径/决议卡路径/未决风险）
```

- **产物路径**：`decisions/G0_选题决议卡.md`（相对**项目工作区根**）。
- **消费方**：`math-model-decomp`、`math-modeling-master`。

## 3. G7 赛后复盘（比赛结束后 48h 内）

### 3.1 三维度归因

- **技术维度**：模型缺陷 / 求解失败 / 图表返工，逐条定位到 CB 门禁（CB-1~CB-12）；
- **协作维度**：交接延迟、产物缺失、沟通返工，标注发生节拍（第几个 12h 同步窗）；
- **时间维度**：各阶段**实际耗时 vs 接力区间预算**（接力区间 = 本阶段收口时刻 − 上一阶段收口时刻）的偏差率，**|偏差率| > 20% 记为异常（含负偏差）**，逐阶段列出偏差值与归因（预算值见 G7 模板第 4 节：72h 赛制合计 72h、96h 赛制合计 96h）。**实际耗时取自 `state/gate_log.jsonl` 中各阶段最后一条 `verdict=PASS` 行的 `ts` 差值（即接力区间实际值），与预算逐阶段比对，|偏差率| > 20% 记为异常（含负偏差）**。
- **根因定位**：统计 `root_cause_phase` 分布，根因最多的阶段列为首要改进阶段；`round>1` 的阶段为高风险阶段。
- **`action` 取值域**：`state/gate_log.jsonl` 的 `action` 取值域为 `proceed / hold / redo_phase / rollback_upstream / fallback_reduce_scope / fallback_alternative / fallback_accept_with_note`；统计 `fallback_*` 三值出现次数作为**降级频次**指标，`redo_phase` 作为**返工频次**指标（读取口径，不改写日志）。

## 4. 策略门禁 S-1 ~ S-5（ASCII 框，本技能自有）

```
+--------------------------------------------------------------------+
| [S-1] 锁题时限：T06:00 未锁题，强制按"数据完备度最高"默认选题      |
| [S-2] 决议留痕：任何选题/换题决定必须写入决议卡，口头无效          |
| [S-3] 否决优先：一票否决红线先于评分卡执行，高分不得豁免           |
| [S-4] 复盘对照：G7 复盘必须逐条过 §3.2 全 17 行审计，缺一行不合格  |
|[S-5] 未来信息隔离：选题评估阶段不得使用题面之外的未来数据做优势判断|
+--------------------------------------------------------------------+
```

- **S-1**：T06:00 仍未产出锁题时间戳 → 自动判定为“数据完备度最高”的候选题，且必须在决议卡第 4 字段补记超时事实；
- **S-2**：任何换题、并题、弃题的口头共识**一律无效**，未落盘即视为未发生；
- **S-3**：§2.2 的 5 条红线在 §2.1 加权求和**之前**执行，被否决题不得因总分高而复活；
- **S-4**：§3.2 审计表 **CB-1~CB-12 共 12 行 + S-1~S-5 共 5 行（合计 17 行）**逐行必填“是/否”，空行即判 G7 不合格、打回补审；
- **S-5**：选题评估只允许使用题面与附件公开信息，**【严禁】**引入题面之外的未来数据或赛后信息做优势判断（对齐 CB-12）。
