# 商业数据分析与决策报告技能 (biz-analytics)

## When to use

1. **经营周报 / 月报**：从订单、流量、客服等多源业务表接入数据，产出带指标异动解释与行动建议的定期经营报告。
2. **渠道归因分析**：对比多投放渠道的获客成本与转化贡献，回答“钱花在哪最值”并给出预算重分配建议。
3. **用户留存与分层分析**：基于 AARRR 或同期群（cohort）拆解留存曲线，定位流失节点并输出干预清单。
4. **销售预测与备货测算**：用时间序列或回归模型对销量/营收做滚动预测，给出置信区间与安全库存建议。
5. **A/B 实验解读**：设计实验、检验显著性、评估业务效应，形成“上线 / 迭代 / 放弃”的决策结论。
6. **管理驾驶舱看板搭建**：把分散指标收敛为指标树与可视化看板，形成可复用的例行监控交付物。
7. **竞品与市场份额对比分析**：对齐口径对比竞品价格、功能与份额，定位自身相对位置，输出份额争夺与定价策略建议。

### Do NOT use when

- 任务是数学建模竞赛论文（国赛/美赛）写作——改用 math-model 家族技能。
- 任务是学术期刊投稿论文，需按期刊模板做文献综述与同行评审式写作。
- 用户只有战略问题而没有任何可接入的数据，属于纯咨询式定性讨论。
- 任务是纯工程代码开发（服务端/前端/算法工程实现），不涉及数据分析结论产出。

## 输入 / 输出契约

路径基准：下表所有相对路径均相对**项目工作区根**（不是 skill 目录）；首次使用前由调用方创建缺失目录。

| 阶段 | 输入 | 输出 | 命名规范 |
|---|---|---|---|
| 1 数据接入与口径对齐 | 源系统导出数据、业务方口径说明 | 数据字典 | `data/data_dictionary.md` |
| 2 数据质量体检与清洗 | 原始数据、数据字典 | 质检报告（含清洗留痕） | `qa/quality_report.md` |
| 3 指标体系搭建 | 业务目标、数据字典 | 指标树与口径公式 | `metrics/metric_tree.md` |
| 4 分析与建模 | 清洗后数据、指标体系 | 分析脚本与结果 | `analysis/*.ipynb`、`analysis/*.py` |
| 5 可视化 | 分析结果、指标体系 | 图表（PNG，300 DPI） | `viz/*.png` |
| 6 结论与建议 | 图表与统计结果 | 结论卡 | `insights/insight_cards.md` |
| 7 交付复核 | 以上全部产物 | 终稿报告与指标字典 | `reports/<日期>_<主题>_分析报告.md`、`reports/*.pptx`、`reports/metrics_dict.csv` |

契约约束：

- 阶段 N 的输出是阶段 N+1 的唯一输入，跳阶段需在质检报告中记录例外原因。
- `data/data_dictionary.md` 必须覆盖源表全部字段；缺失字段不允许进入阶段 2。
- `qa/quality_report.md` 必须记录清洗前/后记录数与丢失比例，作为阶段 7 复核依据。
- `reports/` 中出现的每一个数字都必须能回溯到 `analysis/` 脚本产出或 `viz/` 图表。

## 阶段流程（含 Checkpoint）

### 阶段 1 数据接入与口径对齐

- 活动：源系统确认、字段口径、粒度、时区、主键。
- **Checkpoint 1**：数据字典覆盖全部字段（名称/类型/口径/来源/更新频率）；口径歧义已与业务方书面确认。

### 阶段 2 数据质量体检与清洗

- 活动：缺失/异常/重复/一致性四查；清洗留痕。
- **Checkpoint 2**：清洗前后记录数与损失比例可解释（丢失率 >5% 必须升级审批）；异常值双通道判定（技术性剔除 vs 业务性保留并标注）。

### 阶段 3 指标体系搭建

- 活动：北极星指标 → 拆解树（OSM/UJM 模型）→ 口径公式。
- **Checkpoint 3**：指标树每层可加/可拆、口径公式无歧义、与业务目标对齐。

### 阶段 4 分析与建模

- 活动：描述/归因/预测分层；显著性与置信度。
- **Checkpoint 4**：每个结论标注方法与置信度（p 值/置信区间/样本量）；归因结论区分相关与因果（混杂因素已控制；未控制的已写入风险与局限声明）。

### 阶段 5 可视化

- 活动：图表选型、防重叠、色彩。
- **Checkpoint 5**：每图承载一条结论；图题“对象+图型”；无双 Y 轴，且饼图仅用于 ≤3 类的构成占比；坐标轴不截断，确需截断的已标断轴（二者择一，二者均须在图注中说明）。

### 阶段 6 结论与建议（Insight Cards）

- 活动：结论卡必须含 观察→解释→建议→预期收益→负责人。
- **Checkpoint 6**：每条建议符合 SMART；每条结论可溯源到具体图表与数据；无“建议加强…”式空话。

### 阶段 7 交付复核

- 活动：数字一致性、脱敏、版本；产出 `reports/<日期>_<主题>_分析报告.md`（含模板 8 节）+ `reports/metrics_dict.csv` 指标字典。
- **Checkpoint 7**：报告中所有数字与底表 100% 一致（口径复核）；个人信息已脱敏；结论与建议条数比 ≤1:1（防只提问题不给解法）；建议单条须含责任方与时限（防建议过载）；模板 8 节齐全且指标字典 6 列齐全。

## 质量门禁清单

路径基准：本清单中出现的全部产物路径均相对**项目工作区根**（与上方 I/O 契约表一致，非 skill 目录）。

- [ ] 数据字典完备：全部字段含名称/类型/口径/来源/更新频率（产物 `data/data_dictionary.md`）（阶段 1）
- [ ] 口径歧义已与业务方书面确认，留有确认记录（位置 `data/data_dictionary.md` 口径备注）（阶段 1）
- [ ] 清洗全程留痕，清洗前后记录数与损失比例可解释（产物 `qa/quality_report.md`）（阶段 2）
- [ ] 丢失率 >5% 已升级审批并记录审批人（位置 `qa/quality_report.md` 审批记录段）（阶段 2）
- [ ] 指标树完整：北极星指标可逐层拆解且每层口径公式无歧义（产物 `metrics/metric_tree.md`）（阶段 3）
- [ ] 分析脚本齐备且可复现：`analysis/*.ipynb`、`analysis/*.py` 覆盖全部结论，`reports/` 中每个数字均可回溯到脚本产出（阶段 4）
- [ ] 每个结论标注方法与置信度（p 值/置信区间/样本量）（产物 `insights/insight_cards.md`）（阶段 4）
- [ ] 相关与因果明确区分：混杂因素已控制；未控制的已在报告风险与局限节显式声明，二者必居其一（位置：`reports/<日期>_<主题>_分析报告.md` 第④节『分析方法与假设』内的『相关不等于因果』声明句 + 指标卡 `insights/insight_cards.md` 对应条目的『因果等级』字段）（阶段 4、6）
- [ ] 每张图承载且仅承载一条结论，图题为“对象+图型”（产物 `viz/*.png`）（阶段 5）
- [ ] 无双 Y 轴；饼图仅用于 ≤3 类的构成占比（产物 `viz/*.png`）（阶段 5）
- [ ] 坐标轴不截断，确需截断时已明确标注断轴（产物 `viz/*.png`）（阶段 5）
- [ ] 每条建议符合 SMART（具体、可衡量、可达成、相关、有时限），且含责任方、时限与预期收益（产物 `insights/insight_cards.md`）（阶段 6）
- [ ] 终稿已产出 `reports/<日期>_<主题>_分析报告.md`（含模板 8 节）+ `reports/metrics_dict.csv` 指标字典（阶段 6、7）
- [ ] PPT 版报告已从 markdown 大纲生成且与 `reports/<日期>_<主题>_分析报告.md` 内容一致（阶段 7）
- [ ] 报告所有数字与底表 100% 一致（位置 `reports/<日期>_<主题>_分析报告.md` 全文）（阶段 7）
- [ ] 个人信息与敏感字段已脱敏（位置 `reports/<日期>_<主题>_分析报告.md` 全文）（阶段 7）
- [ ] 报告版本号与生成时间明确标注（位置 `reports/<日期>_<主题>_分析报告.md` 抬头行）（阶段 7）
- [ ] “建议加强…”式空话清零（位置 `reports/<日期>_<主题>_分析报告.md` 第⑦节）（阶段 6）

## 本阶段须通过的门禁

本阶段须通过的门禁 = 上方「质量门禁清单」中带（阶段 N）标注且包含当前阶段编号的全部勾选项（跨阶段条目如（阶段 4、6）分别计入阶段 4 与阶段 6）：任一项未勾选即判该阶段 Checkpoint 不通过，对应产物退回本阶段修订，复检全绿后方可放行下一阶段。

## templates/ 使用说明

配套模板：`biz-analytics/templates/分析报告大纲模板.md`（相对 skill 目录）。

使用方式：

1. 复制大纲模板为 `reports/<日期>_<主题>_分析报告.md`（相对项目工作区根），按模板 8 节骨架顺序填写，不得增删节、不得调序；无内容的节写 `本期无` 并说明原因。
2. 每节必须引用对应契约产物路径（`data/`、`qa/`、`metrics/`、`analysis/`、`viz/`、`insights/`）。
3. 「核心发现」与「可执行建议」两节直接粘贴 `insights/insight_cards.md` 中的结论卡，保持“观察→解释→建议→预期收益→负责人”五段完整。
4. 同步产出 `reports/metrics_dict.csv` 指标字典（6 列表头与模板「指标字典表头」逐字一致）；交付前对照「质量门禁清单」逐项勾选，未通过项不得进入终稿。

## 常见错误

1. 同名指标在不同报表口径不一致，导致“同一指标两个数”，根源是字典未锁口径公式。
2. 清洗直接覆盖原始数据且无留痕，丢失率超阈值也未走审批，事后无法复现。
3. 把相关性当因果结论写入报告（如“投放导致销量上升”），未控制混杂因素也未声明局限。
4. 饼图滥用（类别 >3 仍用饼图）与双 Y 轴并置，视觉上放大或压缩差异。
5. 结论无溯源：报告里的判断找不到对应图表与数据切片，复核时无法验证。
6. 建议不可执行：“建议加强用户运营”这类空话，无负责人、无时限、无预期收益。
7. 一图承载多条结论，图题写成观点句，读者无法对应图与论断。
8. 终稿数字与底表不一致（四舍五入口径不同步），交付复核阶段才暴露。
