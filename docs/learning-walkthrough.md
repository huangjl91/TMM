# 解题引导第一版：从选择题到思考练习

## 使用方式

导入题目后，进入「引导学习」。在读题感知、宏观选型中：

1. 选择一个方向，分别填写三项说明。
2. 不确定时逐级展开提示；提示中的小例子仅用于理解方法。
3. 停笔约 0.7 秒后自动保存；也可点击「保存草稿」或「提交回答，查看反馈」。
4. 缺少内容时留在当前步骤，按追问补充；填写完整后由学生主动点击继续。
5. 点击「针对我的回答追问」会先保存当前回答，再请求教学反馈。配置 AI 时尝试在线分析，否则使用明确标注的本地追问；该反馈不会判分或阻止继续。

输入会先保留本地恢复副本。切换小问时立即提交待保存草稿，保存失败时显示重试提示；重新打开对应小问可恢复尚未写入数据库的回答。已提交的思路不等于已用实验验证。

本版只做填写完整性检查，不将非空回答判成正确答案。模型是否合适，需要结合题目、数据和后续实验核实。

## 读代码的顺序

### 1. 数据和规则：src/shared/learning.ts

`LearningNote` 描述回答、提示等级及是否提交。`LEARNING_TASKS` 定义每一步的学习目标、三个输入字段和三级提示。

`readLearningNote()` 读取保存的 JSON；旧的一句话理由保留在第一项，其余项目待补充。`reviewLearning()` 找出缺项并给出追问。`learningStepReady()` 同时检查已选方向、已提交和填写完整，草稿不会完成步骤。

### 2. 后台流程：src/main/guidedQuiz.ts

`handleGuidedChoose()` 验证步骤和选项，使用后台的选项文本，保存回答并记录反馈。后续步骤提交前检查读题和模型选择是否完成。

`getGuidedState()` 使用同一套规则恢复学习进度。`handleGuidedSync()` 将学生的复述、比较方法和验证计划同步到任务卡。学生改变上游思路时，清除下游当前选择，要求重新核对；使用日志保留之前的尝试摘要。

已有 `guided_choices.user_note` 字段保存结构化数据，不增加数据库表或修改历史迁移。

### 3. 小组件：src/renderer/src/components/LearningTask.tsx

`props` 接收当前回答与保存回调；`map()` 将三个问题渲染为输入框；`onChange` 更新回答；提示按钮保存新的提示等级；反馈区域显示上次提交结果。

### 4. 接入页面：src/renderer/src/components/GuidedQuizPanel.tsx

在现有选项下面放置 `<LearningTask />`。提交完成后先留在原处阅读反馈；另一个按钮负责进入下一步。异步保存返回时核对会话和小问，防止旧请求覆盖新题页面。

### 5. 测试：tests/learning-smoke.mjs

测试使用独立 SQLite 数据库，验证草稿不会过关、缺项反馈、前置要求、不同小问隔离、旧理由保留和同步学生原话。再启动一个独立进程，验证保存的数据可以重新读取。

运行：`npm.cmd run smoke:learning`。

## 第二版新增代码

### 卡点帮助与逐级提示

读题和模型选择练习新增“我现在卡在什么地方”：没读懂题目、不会选模型、不知道怎样验证、不知道怎样解释结果。由学生主动选择，不自动给学生贴能力标签。

`src/shared/learning.ts` 的 `LEARNING_HELP` 保存每类三层提示；`LearningNote` 新增可选的 `helpTopic`、`helpLevel`，继续复用已有回答存储。读取时校验类别、限制等级，旧回答不需要迁移。

`LearningTask.tsx` 的选择框保存类别并重置该组展开等级，按钮每次只展开一级。切换类别不替换学生回答。提示顺序为思考方向、检查方法、类比例子；例子不替学生完成当前题。

`tests/learning-smoke.mjs` 验证跨进程恢复帮助类别与等级，并检查非法类别和过大等级。

- `src/shared/teaching.ts`：定义教学反馈结构、本地追问，以及 AI 输出字段和逐字引文校验。
- `src/main/agent/teaching.ts`：要求 AI 引用原话、指出一个缺口并追问；异常、无效格式或可疑代写内容回退到本地。
- `src/main/guidedQuiz.ts` / `ipc.ts` / `src/preload/index.ts`：从已保存回答读取上下文，通过专用接口返回教学反馈，模型调用仍只发生在主进程。
- `src/renderer/src/lib/draftQueue.ts`：防抖并串行保存；正式提交取消尚未发送的旧草稿，避免覆盖新提交。
- `GuidedQuizPanel.tsx`：维护自动保存状态与本地恢复副本，切换步骤后忽略旧请求的界面结果。
- `tests/teaching-smoke.mjs`：模拟 AI 正常及错误输出，验证回退；模拟慢写入，验证保存顺序、取消和重试。

运行：`npm.cmd run smoke:teaching`。测试不会向真实模型服务发送内容。

## 历史记录与删除

“已删除”列表新增“永久删除”，再次确认后清除本软件的案例附件副本和关联学习记录。外部原始文件及已导出的备份不删除。`src/main/deleteSession.ts` 校验案例已在回收区，检查目录边界与链接后删除专属目录，再通过数据库外键级联清理关联记录。附件被占用时提示失败并保留案例条目，部分文件可能已移除，可释放占用后重试。运行中的案例由主进程阻止永久删除。

`tests/delete-session-smoke.mjs` 使用隔离案例验证删除范围、级联清除、其他案例保留和不可恢复。这里的永久删除指应用内不可恢复，不代表磁盘安全擦除。

### 备份与恢复、复盘引用检查

历史页新增“备份全部案例”和“从备份恢复”。选择位置后保存 `.tmmbackup` 文件，包含已保存的学习记录、实验、附件以及已删除案例，不导出设置中的 API Key。附件合计限 100 MB，未压缩备份限 200 MB。请先保存正在编辑的内容，再备份。

恢复会追加新案例并在标题后标记“恢复”，不覆盖现有案例；原来已删除的案例恢复到“已删除”。重复导入会生成另一份副本。`src/main/backup.ts` 负责格式、路径、附件哈希检查，以及事务写入；任何一步失败会回滚新记录。实验运行编号会映射到新的运行记录。该格式只支持本版数据结构，未来升级需要增加兼容转换。

实验复盘区增加“检查我的证据引用”：`src/shared/predictionLab.ts` 的 `reviewReflection()` 检查指标名、基线和近似匹配的数值，缺少证据时给出追问。它只做本地文本核对，不判断结论对错，也不阻止保存原来的想法。数值匹配允许约 0.5% 的四舍五入差异；不解析完整推理或方法与数值的语义对应。

运行 `npm.cmd run smoke:backup` 验证备份恢复与复盘检查。

日常双击项目根目录的 `启动学习教练.cmd`，或使用 `npm.cmd run dev`，默认均读取 `%APPDATA%/math-modeling-tutor/app.db`。开发版与安装版使用同一固定目录；显式指定 `--user-data-dir` 的测试窗口仍隔离，历史页会显示保存位置。切换窗口不等于数据被清空。

历史页每个案例有删除按钮，确认后移入“已删除”，可以恢复。采用 `sessions.deleted_at` 记录状态，保留笔记和附件；并非从磁盘永久擦除。列表不再限制为最近 50 条。`tests/history-smoke.mjs` 检查跨进程恢复、删除隔离和笔记保留。

## 第三版：预测实验任务卡

### 完整新手练习

点击“开始新题”，再点击“从新手练习开始（合成教学数据）”，会创建独立案例，不覆盖已有历史，也不自动请求 AI。

`src/shared/tutorial.ts` 定义教学题和60天合成客流数据；`src/main/tutorial.ts` 将说明与 CSV 写入新案例并登记附件，写入学习任务的题面。`TutorialRoute.tsx` 按读题、看数据、建立基线、运行、比较、复盘六个环节解释目的和应得到的产物，前五行预览直接取自同一个教学数据生成函数。

用户仍需填写读题和模型选择理由，实际运行 Python 才能得到指标，最后自行保存复盘。题目、文件名、附件摘要与页面均标识教学数据；历史、备份和删除功能同样适用。页面只提供路线说明，不将浏览或填完自动视为掌握。尚未进行外部新手用户试用。

### 初学者入口：术语解释与小步引导

`src/renderer/src/components/PredictionBasics.tsx` 提供预测题的入门帮助，分别放在读题、模型选择和实验准备处。`stage` 参数决定显示哪三个小问题；回答仍填写在原来的输入框中，不额外生成答案或完成标记。

术语词典用原生 `details/summary` 实现，可点击或通过键盘展开。每项包含白话解释、教学例子和本实验中的用途，涵盖目标、模型与基线、训练验证测试、数据泄漏、MAE、RMSE、MAPE、残差及预测区间。教学数字明确与真实实验结果分开。

`LearningTask.tsx` 通过 `prediction` 参数决定是否显示预测入门帮助，`GuidedQuizPanel.tsx` 使用当前题型传入该参数；`PredictionLab.tsx` 在实验计划前复用同一个组件。此改动不修改数据库、已保存回答或实验算法。

在“引导学习”中完成读题复述、模型选择理由后，预测题进入实验任务卡：选择附件、时间列和数值目标，填写单位及运行前预期，保存计划，再运行并填写复盘。实验计划与复盘通过各自的保存按钮保存。

- `src/shared/predictionLab.ts` 定义计划、实验快照与复盘的数据结构，以及缺项提示和指标追问。
- `src/renderer/src/components/PredictionLab.tsx` 用 `useState` 保存当前输入并调用后台接口，四个区域依次引导计划、运行、读证据和复盘。
- `src/main/predictionLab.ts` 检查前置回答，运行预测脚本，保存真实指标和独立图表；比较数据内容的 SHA-256，发现附件修改后要求重跑。
- `src/main/db.ts` 追加 `prediction_labs` 数据表，按会话和小问分别保存。`ipc.ts` 和 `preload/index.ts` 将界面操作连接到后台。
- `src/main/runtime.ts` 优先探测项目 `.venv` 中的 Python；本项目已创建独立环境并安装 `requirements-python.txt`。打包分发时仍需为目标电脑配置运行环境。

学习状态分别显示“思路已提交”“实验已运行/复盘已记录”和“最终结论仍需人工核对”。填写完整、运行成功都不代表结论正确。实验是留出末段数据的一步预测评估，不是未来多期预测。

测试：`npm.cmd run smoke:prediction-lab`。使用独立数据库和明确标记的合成数据，真实运行 Python 沙箱，验证跨进程恢复、按小问隔离、附件改变后证据失效，以及失败时不生成完成记录。
